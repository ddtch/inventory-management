Обзор

Классическое двухуровневое SPA-приложение: браузерный клиент на Vue общается с REST API на FastAPI по HTTP. Серверной базы данных нет: при старте сервер читает JSON-файлы в списки Python и фильтрует их в памяти на каждый запрос.

Клиент

Vue 3 SPA

client/
  • 7 экранов (views): Dashboard, Inventory, Orders, Spending, Demand, Restocking, Reports
  • 9 переиспользуемых компонентов: фильтр-бар, модальные окна, меню профиля, переключатель языка
  • 3 composable: фильтры, i18n (en/ja), мок-авторизация
  • Графики нарисованы вручную на SVG и CSS Grid, без chart-библиотек
Сервер

FastAPI REST API

server/main.py · 309 строк
  • 17 эндпоинтов, один POST (restocking)
  • Pydantic-модели как response_model для валидации ответов
  • Две утилиты фильтрации: apply_filters и filter_by_month
  • CORS открыт для всех источников (демо-режим)
Данные

JSON в памяти

server/data/*.json · server/mock_data.py
  • 7 файлов: inventory, orders, demand_forecasts, backlog_items, spending, transactions, purchase_orders
  • Загружаются один раз при импорте модуля
  • Период данных: январь–сентябрь 2025
  • Изменения не сохраняются, перезапуск перечитывает файлы

Архитектура системы

Компоненты и связи между ними. Сплошные стрелки: синхронные HTTP-запросы и импорты модулей. Пунктир: эндпоинты, которые вызывает клиент, но которых нет на сервере.

Клиент и сервер запускаются как два отдельных процесса. Браузер обращается к API напрямую по абсолютному URL, прокси в Vite не настроен, поэтому на сервере включён CORS.

Потоки данных

Три сценария, которые покрывают почти всю логику приложения.

1. Старт сервера: загрузка данных в память

1

uvicorn запускает main.py, который импортирует mock_data.

server/main.py:5
2

mock_data.py при импорте вызывает load_json_file() для каждого из 7 файлов и кладёт результат в модульные переменные: inventory_items, orders, demand_forecasts, backlog_items, spending_*, recent_transactions, purchase_orders.

server/mock_data.py
3

Данные живут как обычные списки словарей до остановки процесса. Эндпоинты никогда не мутируют их, а фильтруют через list comprehension в новые списки.

server/main.py · apply_filters, filter_by_month

2. Основной сценарий: изменение фильтра на Dashboard

1

Пользователь меняет Time Period / Warehouse / Category / Order Status в FilterBar.

client/src/components/FilterBar.vue
2

FilterBar пишет в общие ref-ы composable useFilters. Это singleton: рефы объявлены на уровне модуля, поэтому все экраны видят одно и то же состояние фильтров.

client/src/composables/useFilters.js
3

В Dashboard.vue стоит watch([selectedPeriod, selectedLocation, selectedCategory, selectedStatus]), который перезапускает загрузку. Параллельно через Promise.all уходят 4 запроса: summary, orders, inventory, backlog.

client/src/views/Dashboard.vue:567-570, 676
4

api.js собирает URLSearchParams, пропуская значения 'all', и вызывает axios. Период маппится в параметр month: либо 2025-03, либо квартал Q1-2025.

client/src/api.js
5

FastAPI принимает query-параметры как Optional[str]. apply_filters последовательно отсекает по warehouse, category (регистронезависимо) и status; filter_by_month ищет подстроку месяца в order_date, для кварталов разворачивает QUARTER_MAP в три месяца.

server/main.py:17-47
6

Для /api/dashboard/summary сервер сам считает агрегаты: стоимость запасов, число позиций ниже reorder point, pending-заказы, сумму заказов. Для списков ответ валидируется Pydantic через response_model.

server/main.py:182-208
7

Сырые ответы попадают в ref-ы (allOrders, inventoryItems, …). Вся производная аналитика для графиков (statusData, categoryData, orderTrendData, topProducts) считается в computed на клиенте и автоматически перерисовывает SVG.

client/src/views/Dashboard.vue:343-589
Особенность фильтра по времени. Инвентарь не имеет временного измерения, поэтому /api/inventory игнорирует month, а /api/demand, /api/backlog и /api/spending/* не принимают фильтры вовсе. Фильтр-бар при этом виден на всех экранах.

3. Локализация и валюта

1

LanguageSwitcher меняет currentLocale в useI18n (singleton, значение сохраняется в localStorage под ключом app-locale).

client/src/composables/useI18n.js
2

Функция t('nav.overview') ищет ключ в locales/ja.js, при промахе откатывается на en.js. Валюта выводится из локали: ja даёт JPY, иначе USD. Это чисто клиентский поток, сервер о языке не знает.

client/src/locales/, client/src/utils/currency.js
3

useAuth не ходит на сервер: пользователь и его задачи захардкожены и переключаются между английским и японским вариантом по той же локали.

client/src/composables/useAuth.js

Замечания по коду

Расхождения, которые видны при сопоставлении клиента и сервера.

Клиент вызывает несуществующие эндпоинты. В api.js есть методы getTasks, createTask, deleteTask, toggleTask (/api/tasks), а также createPurchaseOrder и getPurchaseOrderByBacklogItem (/api/purchase-orders). В main.py этих маршрутов нет. App.vue вызывает api.getTasks() при монтировании, получает 404 и глушит ошибку в console.error. Задачи в модальном окне берутся только из мок-данных useAuth.
Backlog.vue не подключён к роутеру. Файл существует в views/, но маршрута для него в main.js нет. Бэклог показывается внутри Dashboard.
purchase_orders.json пустой (3 байта: []), поэтому флаг has_purchase_order у всех позиций бэклога всегда false.
Безопасность только для локальной разработки. Нет аутентификации, CORS открыт для всех источников, URL API захардкожен в api.js.

Запуск

Одной командой или по отдельности.

# Всё сразу (из корня проекта)
./scripts/start.sh          # остановить: ./scripts/stop.sh

# Бэкенд
cd server && uv venv && uv sync && uv run python main.py     # http://localhost:8001/docs

# Фронтенд
cd client && bun install && bun run dev                        # http://localhost:3000

# Тесты
cd tests && uv run pytest backend/ -v
